## 1. 背景（执行前必读，约 200 字）

公司每周从「物品放行系统」导出 100 多 MB 的 Excel（十几万单、约 40 列、一单多行），Excel 打不开、看板也吃不下（浏览器解析 xlsx 有约 512MB 解压上限）。所以做了个**清洗引擎**：

- `etl_engine.py`：只用 Python 标准库，流式读 xlsx/CSV，按「配方」把原始数据聚合成周报数据 + 一份可拖进看板的明细子集。
- `recipes/weekly_overtime.json`：配方（阈值、时长分档、看哪些维度、明细子集规则）。**需求要变时只改这个文件。**

业务口径（引擎已实现，验收时用来判断数字对不对）：
- **特保单**：`放行單號` 以 `WF9897` 开头（旧 `WF8888` 规则已废弃）
- **已到达**：该单任一行 `實際放行門崗` == `放行單流入門崗`
- **放行超时**：`放行超時` 列是**超时分钟数**，`> 0` 即超时（不是 0/1 标记）
- **接收超时**：`接收超時` 分钟数 `> 0`
- **超时未接收**：已到达 且 接收超时 `>0` 且 `接收時間` 为空
- **在途超时**：未到达 且 放行超时
- **结案**：已到达 且 非在途超时。「放行拒绝」**不算异常**，照常计入结案
- **一级部门**：`申請人部門` 去掉末尾 `_厂区`，再取第一个空格前那段（`MFG 網站 SW 自動化1組_鄭州` → `MFG`）

## 11. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `py` 不是内部或外部命令 | 没装 Python Launcher | 改用 `python`，或 `where python` 找到解释器全路径 |
| `MemoryError` / 进程被杀 | 32 位 Python，或同时开了 Excel/浏览器 | 确认位数（第 2 节）；关掉其它程序重试一次；仍失败则记录并报告 |
| `前 25 行里没找到可识别的表头` | 导出文件前几行是标题/说明；或多 sheet 且第一个是空表 | 回传文件前 5 行原文（脱敏），不要自行改引擎 |
| 中文乱码 | CSV 编码不是 UTF-8/GBK | 引擎已自动尝试 `utf-8-sig / gbk / utf-8`；仍乱码就把文件前 200 字节 hexdump 回传 |
| `OSError: [Errno 22] Invalid argument` | 输出目录被 OneDrive/杀软占用 | 把 `--out` 指到本地非同步盘（如 `D:\dsh_etl\out`），引擎已内置重试 5 次 |
| xlsx 读取极慢（>30 分钟） | 文件在网盘/共享盘上（网络 I/O） | 先把文件复制到本地磁盘再跑 |
| 看板载入后数字全 0 | 拖的是原始大文件或列名不符 | 确认拖的是 `09_明细_超时单.csv`；回传该文件前 2 行 |
| `PermissionError` 覆盖输出 | 旧输出还被 Excel 打开着 | 关闭 Excel 相关文件后重跑 |
