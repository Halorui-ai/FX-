## 4. 数据字段

全部**订单级**。六张卡读同一个「范围」（§4.1）过滤后的订单集。

### 4.1 范围 ALL / MP / NPI（新）

| 值 | 订单集 |
|---|---|
| ALL | 全部放行单 |
| NPI | `o.特保`（单号前缀 `WF9897`） |
| MP（量产） | `!o.特保`，即 NPI 以外全部 |

范围是 GDMS 六卡共享的界面状态，不持久化，默认 ALL。控件放在 `gdms_timeout_trend` 卡头；范围不是 ALL 时，其余五卡标题旁显示「范围 MP / NPI」徽标。布局里没有 `gdms_timeout_trend` 时按 ALL 处理。其它视图里的非 GDMS 卡不受范围影响。

实现：新增 `computeGdmsStats(scope, grain)`，只读 `orders`，按 `scope|grain` 缓存，数据变更时与 `_statsCache` 一起失效。不要把范围塞进 `computeStats()`。

### 4.2 一级部门归并规则（新）

`申请部门` 原文形如 `MFG 網站 SW 自動化1組_鄭州`、`MLB 撕石墨片 A線_ZZ`。

1. 去掉首尾空白；
2. 去掉最后一个下划线及其后的厂区后缀（`_鄭州`、`_ZZ`）；
3. 取第一个空白字符之前的部分作为一级部门（`MFG`、`MLB`、`FATP`、`物流`…）；
4. 没有空白的整段保留；空值归「（空）」；
5. `CONFIG.GDMS.部门归并` 可写前缀例外表（如 `{ "設備工程": "設備" }`），命中则优先。默认空表。

只用于 `gdms_timeout_dept`。`chart_dept`、`gdms_receive_dept` 仍按部门原文。

### 4.3 超时时长分档（新口径，替换现行 `timeoutByDuration`）

现行算法是「申请日期 → 当前时刻」，历史数据几乎全落 `X>4H`，弃用。

**业务定义（用户 2026-11-12）**：超时时长 = 上一个门岗放行之后，下一个门岗该放行而没放行，隔了多久。

**取数（待用户确认）**：准确导出里 `放行超时` 列本身就是**超时分钟数**（D-36），系统已按上述定义算好，直接用：

- 每单超时时长 = 该单各记录 `放行超时` 分钟数的最大值；只对 `o.放行超时` 的单计算。
- 需在 `normalizeRow` 留 `_放行超时分钟`（数字，非数字记 `null`），`computeOrders` 带出 `放行超时分钟`。
- 分四档：`X≤30min` / `30min<X≤1H` / `1H<X≤4H` / `X>4H`，档界放 `CONFIG.GDMS.时长分档`。
- **兜底**（旧导出只有是/否标记、没有分钟数）：按门岗间隔推算——在途超时取「最后一次放行时间 → 数据最新时刻」，到达超时取「打标记那笔与其前一笔放行时间之差」，起点缺失用申请时间；卡片底注写明「按门岗间隔推算」。
- 分钟数与推算都取不到的单不计入，底注写「N 单缺时间未计入」。

说明：在该文件上，分钟数列与「门岗间放行间隔」并不相等（77 笔超时记录里，间隔 39~1189 分钟，分钟数 41~589 分钟）——分钟数是**超出时限的部分**，间隔是**总共隔了多久**。四档界限（30 分钟起）对应的是前者，故优先取分钟数列。

## 5. 交互

- 范围、粒度两组 Tab 用 `.kpi-seg`，点击不打开详情；切范围重渲六卡，切粒度只重渲趋势卡。
- 8 格：「放行单总数」打开现有详情 `overview`，「NPI物料」打开 `special`；其余六格本期不下钻。
- 查询表：单号是 `.orderLink`（进单据追踪）；表内最多显示 50 单并注明总数；「导出」用现有 FileSaver 导出**当前范围 + 当前状态**的全部单，CSV 带 BOM，6 列，文件名含范围与日期。单元格经 `escapeHtml`。
- 查询表不再整卡点击进 `transitTimeout` 详情（卡内已有筛选与导出，避免误触）。
- 部门卡：超时率 ≥ 预警值的部门，其折线点标签用 `--bad`。
- 无数据：图表卡显示「✅ 当前范围内没有放行超时单」。
- 演示模式 `update`：六卡走 `setOption` 增量刷新，保留当前范围 / 粒度 / 表格状态与滚动位置。
- 拖拽缩放仍走现有 gridstack。
